# AGY Gemini 性能优化交接

用户于 2026-10-20 明确要求：由 `agy` 的 **Gemini 3.8 Flash (High)** 接手，以 Pele 性能的 **10 倍**为目标持续优化，每轮完成后适时提交并推送。实际模型 ID 为 `gemini-3.8-flash-high`，推理 effort 为 `high`。不要替换模型，不恢复已停止的 Claude 会话。

## 目标与测量口径

- 主目标：固定 Pele 1.7.0 `8603bf3313add9143cd417015d4a6bd6c522dada`，沿用全部 **167 个原始样本、33 类图表**，API 返回口径下 Rust 相对 Pele 的逐类型加速比等权几何平均达到 **10×**。
- 每一项计时均包含完整解析、布局和 SVG 生成。不得通过预解析、返回缓存、减少输入、跳过类型、降低精度、简化输出或改变 Node/Rust 的工作量达标。
- 同时独立报告 UTF-8 就绪口径、各类型分布和最慢类型。UTF-8 口径或少数类型达到 10× 不等于主目标达到；平均达到也不能表述为每类均达到。
- 保持三轮独立进程、交替先后顺序、5 批预热、至少 10 ms 校准、至少 9 个样本且累计至少 300 ms 的既有协议。输出验证不计入计时。编译、测试、CPU 采样和分配探针不得与计时重叠。
- 另外保留原有 **39 组扩展负载**和原始压力测试。不能只优化短样本而掩盖大图回退；所有回退行和原始采样都必须保留。
- 10× 是持续追求的目标，尚未达成，也尚未证明在现有兼容性约束下可达。遇到收益瓶颈应记录证据并改换有依据的方案，不得伪造达标结论。

## 连续执行方式

1. 接手后先读取上述文件，检查工作区、分支和远端；确认没有其他执行器同时编辑或计时。更新实施状态中的接手情况。
2. 每轮选择有 profiling 证据的瓶颈，写清假设，保存输入、源码和优化前程序的指纹。为每轮使用新的 `target/` 目录，冻结基线后才修改源码。
3. 优先研究能带来结构性收益的布局数据结构、重复遍历、解析与模型构造、文本测量和 SVG 写入成本。前几轮已处理基础字符串复制和共享缓冲区，不能预设继续做微小改动就会达到 10×。
4. 实现后执行相关回归、全工作区测试、完整响应/SVG 对照及原超时门禁。原测试输入、断言、预期值、随机种子、循环次数和性能阈值不得修改。既有 fixture 不得用 Rust 输出重生成。
5. 对通过正确性验证的候选运行完整前后配对基准和当前 Rust/Pele 对比，分别记录时间、分配次数、累计申请字节及峰值。正确性回退必须修复；没有收益的实验明确记录，不混入成功结果。
6. 每个完成验证的优化轮次更新实施状态、技术报告和复现证据，并适时 `git commit`、`git push origin main`。不强推，不撤销用户或其他会话的修改。发布文档前确认数据对应提交的实际源码。
7. README 默认英文，保留渲染和性能对比，只展示当前终态，仅在开头提一次移植与对齐版本。消费者安装示例使用远程 Git 地址并锁定已验证的代码提交，不使用本地 `path` 依赖。
8. 一轮完成后继续下一轮，直到主目标有完整证据支撑，或用户明确停止/调整目标。不要只提出建议就结束。若遇到认证、额度、权限或必须改变验收范围的阻碍，记录真实原因和断点；不要绕过权限、私自换模型或放松标准。
