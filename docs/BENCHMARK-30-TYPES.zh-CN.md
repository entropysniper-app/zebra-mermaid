# Rust 与 Pele 性能对比

> Historical 30-type snapshot. Current results: [33-type benchmark](BENCHMARK.zh-CN.md) and [Pele protocol](BENCHMARK-PELE-PROTOCOL.zh-CN.md).

测量时间：2026-10-19T07:53:04.165Z。固定 Pele 提交：`44da152bbb79b91f03e68016f42499bb25bf6e82`。

本次只对已实现的 30 类图表给出速度比。39 组工作负载中 35 组的每个输入都成功，SVG 的 UTF-8 FNV-1a-64 校验值及尺寸一致；4 组未完成类型不参与速度比较。FNV 校验用于基准前检查，完整逐字节对照仍由兼容测试承担。

## 测量条件

- 硬件与操作系统信息未纳入公开报告；结果仅描述本次测量，不作为跨平台结论。
- rustc 1.96.1 (31fca3adb 2026-06-26)；Node v26.3.0。Rust release、thin LTO、codegen-units=1；Pele 使用已构建的生产 bundle。
- 两边使用相同输入、CSS 输出、默认 Arial 估算测量器、UTC 与固定 now=1792368000000；parse 和完整 render 分别计时，不使用预解析或缓存替代完整渲染。
- 三轮独立进程，交替运行顺序；每组预热 5 个批次，校准重复次数使计时片段至少约 10 ms。每轮至少 9 个样本且累计至少 300 ms，取每轮中位数，再取三轮中位数。
- 计时期间未并行运行编译或测试。计时包含返回结果释放；不包含基准前的 SVG 校验和 JSON 报告写出。
- 下表单位为 **ms/整批输入**，不是每张图；Rust/Pele 小于 1 表示 Rust 更快。范围是三轮各自中位耗时比的最小到最大值，不是统计置信区间。

30 类文档工作负载的 render 耗时比几何平均为 **0.956**。这是每类等权的指标，不能代表任意真实应用的总体速度。

## 进程启动与单图渲染

用同一份 4 节点流程图，分别启动 Rust CLI 和导入 Pele 的 Node 参照脚本，验证完整 SVG 一致。预运行后各测 30 次，交替顺序。

| 运行方式 | 中位耗时 ms | 最小–最大 ms |
| --- | ---: | ---: |
| Rust CLI | 2.029 | 1.587–2.353 |
| Node + Pele 参照脚本 | 69.475 | 67.990–73.324 |

该项包含进程创建、动态库/模块加载、输入输出及一次渲染，使用已热的文件系统缓存。Node 参照脚本不是 Pele 官方 CLI，不能把比值说成渲染算法的加速倍数。

## 体积与限制

- 本次 30 类 Rust CLI 文件：4,129,616 bytes（未单独 strip）。
- Pele 生产 JS bundle：678,032 bytes；运行它还需要 Node。两种文件形态不同，不能直接用尺寸比断言部署优势。
- 尚未测量峰值内存、分配次数、CPU profile、其他平台以及完整 33 类。
- info、journey、block、xychart 等组仍有慢于 Pele 的结果；当前不满足所有类别不持续慢 20% 的候选性能目标。
- 本报告不代表 6,810 项原始测试已经全部移植通过，测试验收单独维护。

## 复现与原始数据

`tools/bench/cases.mjs` 生成输入，release 构建需启用当前已实现的全部 30 类。`tools/bench/run.mjs` 默认使用 `target` 下的二进制，或通过 `CARGO_TARGET_DIR` 指定。

```sh
node tools/bench/cases.mjs
CARGO_TARGET_DIR=target node tools/bench/run.mjs
node tools/bench/compare.mjs
```
